## 2. План разработки (спринты по 2 недели)

| Спринт | Цель | Результат (Definition of Done) |
|---|---|---|
| **0. Фундамент** (1 нед.) | Монорепо, docker-compose, CI, Postgres + Alembic, Qdrant, MinIO, каркас FastAPI и Next.js с токенами дизайна | `docker compose up` поднимает всё; health-check; пустые экраны с темами и KZ/RU |
| **1. Ингест законов** | Парсер Adilet → дерево `legal_units` (kk+ru) для Закона «О жилищных отношениях», КоАП, ГК (обе части); чанкинг; bge-m3; индекс Qdrant | Команда `ingest run ZHO` загружает акт; юнит-тесты на разбор статей/пунктов; админ-просмотр дерева |
| **2. RAG-ядро + нормализатор** | Exact resolver, dense, sparse, RRF, reranker; нормализатор шала-қазақша; **золотой eval-набор 150+ вопросов** (≥40% смешанных/с ошибками), размеченный юристом | Recall@10 ≥ 0.85 по eval; отчёт по каждому промаху |
| **3. Case Analyzer + чат** | Промпт юриста, structured output, верификатор цитат, SSE-стрим, сохранение дел/сообщений, UI чата с карточками ответа и панелью источников | 0 непроверенных цитат на eval; ручная оценка юристом ≥ 80% «корректно» |
| **4. Action Plan + калькуляторы** | Маршрут дела в UI, калькулятор пени (справочник ставок с историей), калькулятор кворума (сетка + циферблат), пороги из БД со ссылкой на нормы | Калькуляторы покрыты тестами на граничные случаи; юрист подтвердил пороги |
| **5. Document Builder** | 7 шаблонов kk/ru (претензия, жалоба в жилинспекцию/eOtinish, акт о затоплении, протокол собрания + бюллетень, 2 иска), извлечение полей из диалога, мастер, .docx/.pdf | Документ из чата формируется < 10 с; юрист проверил шаблоны |
| **6. Document Review + расширение базы** | Загрузка PDF/DOCX/скан (OCR kaz+rus), разбор на пункты, проверка по RAG; добавить ЗоЗПП, Предпринимательский кодекс, «О естественных монополиях», правила предоставления коммунальных услуг, СанПиН, ППБ, типовые документы ОСИ | Находки с нормами; защита от prompt-injection протестирована |
| **7. Справочник НПА, кабинет, админка** | Справочник с поиском и редакциями, профиль, «дом» для ОСИ, админка: статус редакций, разметка ответов, ежесуточный diff Adilet | Обновление закона автоматически переиндексируется |
| **8. Production** | Нагрузочные тесты, безопасность (OWASP, PII-scrubber), мониторинг, бэкапы, размещение в РК, юридический дисклеймер и оферта | Публичная бета |

Параллельно весь проект: юрист-методолог размечает ответы → пополняется eval-набор → каждое изменение промптов/поиска проходит **eval-gate в CI**.

## Итоги Спринта 2 — оценка поиска (15.11.2026)

Набор: `apps/api/tests/eval/retrieval_gold.jsonl`, 174 вопроса (смешанные, с опечатками и латиницей ≈ 40%), черновик — нужна проверка юристом.
Нормализатор — запасной режим без LLM (ключа Anthropic пока нет).

| Режим | R@1 | R@5 | R@10 | MRR | сек/запрос (M2, 8 ГБ) |
|---|---|---|---|---|---|
| Базовый, без реранкера | .523 | .787 | .862 | .63 | 0.3 |
| + глоссарий и транслит, без реранкера | .695 | .868 | .925 | .765 | 0.23 |
| + реранкер, пул 40, длина 512 | .770 | .908 | .937 | .833 | 23 |
| + реранкер, пул 20, длина 384 | .776 | .914 | .931 | .836 | 25 |

Цель R@10 ≥ 0.85 достигнута. Слабое место — смешанные вопросы (R@10 .82, R@1 .58); основное
улучшение ожидается от LLM-нормализатора. Реранкер поднимает R@1 на ~8 п.п., но на ноутбуке
без GPU слишком медленный — локально выключен (`RERANK_ENABLED=false`), на сервере включить на GPU.

## Спринт 3 — Case Analyzer + чат (15.11.2026, первая часть)

Сделано:
- `app/services/lawyer/`: `schema.py` (формат ответа и JSON-схема), `context.py` (блок `<context>` с chunk_id, статьёй,
  пунктом, датой редакции и ссылкой на Adilet), `generator.py` (Claude: адаптивное мышление, effort high, structured
  output, стриминг, server-side fallbacks, кэш системного промпта; демо-режим без ключа), `verify.py` (верификатор
  ссылок), `pipeline.py` (нормализация → поиск → ответ → проверка → сохранение), `store.py` (дела, сообщения,
  цитаты, трасса поиска; пока на гостевого пользователя).
- `POST /v1/chat` (SSE: status, normalized, sources, delta, answer, notice, error, done), `GET /v1/chat/status`,
  `GET /v1/cases/{id}`. Промпт юриста вынесен в `app/prompts/lawyer.md`.
- Веб: страница `/[locale]/chat` — этапы обработки, потоковый текст, карточка ответа (основание с цитатами, кто отвечает,
  оценка, план, документы, уточняющие вопросы), панель источников; поле на главной ведёт в чат.

Верификатор: ссылка на chunk_id вне контекста удаляется; номер статьи/пункта и название акта берутся из контекста;
цитата, которой нет дословно в тексте пункта (на любом из языков), заменяется настоящим текстом; статьи, названные в
тексте ответа, но не найденные поиском, помечают ответ `needs_review`.

Осталось: прогон с `ANTHROPIC_API_KEY` на eval-вопросах (цель — 0 непроверенных цитат), ручная оценка юристом,
вход в аккаунт вместо гостевого пользователя, список дел пользователя.

## LLM через локальный Claude Code (15.11.2026)

`LLM_PROVIDER=claude_code` — AI-юрист вызывает `claude -p --output-format json` (обёртка
`app/services/llm/claude_code.py`: `ask_llm(prompt) -> str`, `ask_llm_async`, таймаут, ClaudeCodeError /
Unavailable / Timeout / Failed). Дочернему процессу не передаются ANTHROPIC_API_KEY / AUTH_TOKEN / BASE_URL и
служебные CLAUDE_* переменные; запуск в пустом временном каталоге без инструментов. Ответ проверяется по схеме,
одна повторная попытка. Нормализатор в этом режиме — эвристический. Режим только для разработки на компьютере
владельца подписки; для публичного сайта — `LLM_PROVIDER=anthropic` и API-ключ.

## Админка (16.11.2026)

`/[locale]/admin` — вход сотрудников (JWT, пароли scrypt), роли: admin (законы, редакции, сотрудники) и lawyer

## RAG: расширение и улучшения (16.11.2026)

**База.** +4 акта (всего 15): Перечень и Типовые правила предоставления коммунальных услуг (V2000020542,
`COMM_SERVICES`), ЗРК «О защите прав потребителей» (Z100000274_, `CONSUMER`), ЗРК «О естественных монополиях»
(Z1800000204, `MONOPOLIES`: тарифы, публичные слушания), Строительный кодекс РК 2026 (K2600000253, `STROY`:
перепланировка, обязанности собственников). Закон «Об архитектурной, градостроительной и строительной деятельности»
(Z010000242_) не добавлен: утратил силу с 01.07.2026 (заменён Строительным кодексом). Загружено через админку,
без остановки API. Фрагментов в поиске ~45 тыс.

**Отсылочные нормы** (`app/services/rag/xrefs.py`). Пункт «в порядке, предусмотренном пунктом 3 статьи 42
настоящего Закона» сам по себе неполон. Из 5 лучших найденных пунктов извлекаются однозначные отсылки
(«настоящего Закона/Кодекса», «осы Заңның N-бабы», или акт назван по имени: «статьи 917 Гражданского кодекса»),
и до 4 указанных норм добавляются в контекст в той же редакции по дате события (для ссылки на статью целиком —
ближайший к вопросу пункт). В контексте у них `role="cross_reference"` и `referenced_from`, в панели источников —
метка «по отсылке из ст. N». Отсылки без названия акта не угадываются.

**Иерархия.** У каждого фрагмента в контексте атрибут `level` (1 Конституция … 5 приказ); промпт велит при
расхождении применять вышестоящий акт и говорить об этом.

**Разнообразие выдачи** (`diversify` в `retriever.py`). Раньше 5 подпунктов одного перечня («art51-5/p2/sp7»,
«…/sp10», «…/sp12») вытесняли другие статьи. Теперь не больше 2 подпунктов одного пункта и 3 единиц одной статьи
(статьи, названные в вопросе, не ограничиваются).

**Словарь** (`glossary.py`): горячая вода, отопление, свет, газ, перерасчёт, тарифы, счётчики, потребитель,
разрешение на перепланировку — запросы дополняются юридическими терминами.

**Контроль качества.** Контрольный набор вырос до 186 вопросов, эталон может указывать акт («COMM_SERVICES:p21/sp7»).
Админка → «Законы» → «Качество поиска»: кнопка «Проверить качество» запускает набор фоновой задачей и показывает
R@1/R@5/R@10, точность по актам и список промахов (`POST/GET /v1/admin/eval/retrieval`).

**Qdrant-сервер (17.11.2026).** Вместо встроенного режима — Qdrant 1.20.0 (бинарник с GitHub, sha256 сверен),
`data/qdrant_server/run.sh`, только localhost, без телеметрии; `.env`: `QDRANT_URL=http://localhost:6333`.
42 780 векторов перенесены без пересчёта. Поиск ~0,2 с вместо ~2 с, нет блокировки — индексация и оценка идут
параллельно с API. Порядок запуска: сначала `run.sh`, потом API.

**Модели в fp16** (`ML_DTYPE=auto`): на Mac с 8 ГБ две fp32-модели (~4,5 ГБ) уходили в своп — реранкер работал
десятки секунд. В fp16 на MPS: +~2 с на вопрос. Реранкер включён (`RERANK_ENABLED=true`).

**Приоритет иерархии** (`LEVEL_WEIGHTS` в `retriever.py`): очки приказов (уровень 5) ×0,85, и в RRF, и после
реранкера. Кворум есть и в ЗРК (ст. 42 п. 8), и в Правилах (п. 11) — первым должен идти закон.

## Документ в чате (17.11.2026)

Навык AI-юриста по замечанию ментора: документ собирается прямо в деле, а не на отдельной странице.

- **Запуск.** В ответе AI у предложенного документа кнопка «Составить в чате»; кнопка 📄 у поля ввода — любой
  из 6 шаблонов. Черновик привязан к делу (`document_drafts`, миграция 0002) и восстанавливается при открытии дела.
- **Заполнение.** Сразу — однозначные факты из переписки (номера квартир, сумма в тенге, дата, ИИН, телефон).
  В фоне LLM дочитывает переписку и заполняет пустые поля только явно названными фактами (`/autofill`).
  Потом карточка спрашивает недостающее по одному: обязательные поля, затем полезные необязательные (их можно
  пропустить). Есть режим «Заполнить всё формой».
- **Приложения.** Для каждого шаблона — чек-лист (обязательно / желательно / по желанию): удостоверение,
  документ о собственности, акт, оценка ущерба, претензия, фото, квитанция госпошлины. PDF и фото до 10 МБ.
  Файлы лежат в `data/uploads/<черновик>/` (вне git), **в LLM не отправляются**; удаление черновика удаляет файлы.
- **Результат.** .docx, где раздел «Приложения» собран из реально загруженных файлов, или .zip:
  «01 Иск….docx», «02 Удостоверение личности.pdf», «03 …».
- API: `POST/GET/PATCH/DELETE /v1/documents/drafts[/{id}]`, `/autofill`, `/files`, `/files/{id}`, `/preview`,
  `/docx`, `/package`.

Ограничения: доступ к черновику — по его UUID (входа для жителей ещё нет); хранение удостоверений и справок
требует решения по локализации персональных данных в РК до запуска в интернете.

## Демо для ментора через туннель (17.11.2026)

`scripts/demo.sh build|web|tunnel`: продакшен-сборка сайта (`apps/web/.next-demo`, отдельно от `next dev`) на :3001,
весь сайт и API закрыты паролем (HTTP Basic, пароль в `.env.demo`, логин любой), API проксируется через тот же адрес
(`/backend/*` → :8000), публичная ссылка — Cloudflare quick tunnel (`data/tools/cloudflared` 2026.10.7, sha256 сверен).
`caffeinate` не даёт Mac уснуть. Ссылка `*.trycloudflare.com` новая при каждом запуске туннеля.
Чат шлёт SSE-комментарий `: ping` каждые 15 с — иначе Cloudflare рвёт поток, пока Claude Code готовит ответ.
Порядок запуска: Qdrant → API → `demo.sh web` → `demo.sh tunnel`. Только для показа: AI работает через личную подписку.
